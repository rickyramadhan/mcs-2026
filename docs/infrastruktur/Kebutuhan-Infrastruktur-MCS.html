Tentang dokumen ini

Dokumen ini menjelaskan perkiraan kebutuhan server, penyimpanan, jaringan, dan keamanan apabila prototipe MCS dikembangkan menjadi sistem yang digunakan seluruh bidang Pidana Militer Kejaksaan di Indonesia.

Perhitungan disusun dari asumsi jumlah pengguna, jumlah perkara, dan jenis dokumen yang umum dalam penanganan perkara. Angka akhir akan berubah setelah Kejaksaan memberikan data riil, terutama jumlah perkara per tahun dan kebijakan dokumen yang wajib diunggah.

Prototipe yang ada saat ini (mcs-2026.vercel.app) belum memiliki server maupun database; seluruh data di dalamnya adalah data contoh. Dokumen ini menggambarkan kebutuhan untuk sistem final.

Kapasitas skenario B = dokumen 5 tahun (±3,5 TB) + revisi & OCR (±0,9 TB) + migrasi data lama (±1–3 TB) + cadangan pertumbuhan ±30%.

5.4 Strategi agar hemat

  • Penyimpanan berjenjang: dokumen perkara yang sudah eksekusi lebih dari 2 tahun dipindah ke storage arsip (HDD kapasitas besar) yang lebih murah.
  • Kompresi otomatis saat unggah: ukuran scan turun 40–70% tanpa mengurangi keterbacaan.
  • Satu file disimpan sekali: dokumen identik yang diunggah ulang tidak disimpan ganda.
  • Watermark dibuat saat dokumen dibuka: tidak menambah file baru.
  • Batas ukuran unggah: misalnya maksimal 100 MB per PDF; video melalui jalur unggah khusus.
  • Standar scan baku: hitam-putih / abu-abu 200–300 dpi untuk berkas teks; warna hanya untuk foto.

Jika Kejaksaan sudah memiliki perangkat firewall/WAF, SSO, atau sistem backup terpusat, komponen tersebut dapat memakai yang sudah ada sehingga kebutuhan VM berkurang.

Mengapa spesifikasi ini cukup

  • Satu server aplikasi 8 vCPU sanggup melayani ratusan pengguna bersamaan untuk aplikasi kerja seperti MCS; dua server memberikan cadangan sekaligus kapasitas dua kali lipat.
  • Database 32 GB RAM mampu menampung seluruh data aktif perkara di memori sehingga pencarian & dashboard tetap cepat.
  • Pengolah dokumen dipisah agar proses OCR/kompresi berkas besar tidak memperlambat layar pengguna.

LLampiran: rumus perhitungan

Storage dokumen per tahun = (jumlah perkara Oditurat × ukuran per perkara Oditurat) + (jumlah perkara koneksitas × ukuran per perkara koneksitas) Skenario B = (4.500 × 70 MB) + (500 × 800 MB) = 315 GB + 400 GB ≈ 0,7 TB / tahun Kapasitas 5 tahun (skenario B) = 0,7 TB × 5 ≈ 3,5 TB (dokumen baru) + 25% ≈ 0,9 TB (revisi + pratinjau/OCR) + migrasi data lama ≈ 1–3 TB + cadangan pertumbuhan ≈ 30% ≈ 8–10 TB usable Backup ≈ 2,5 × storage utama ≈ 20–25 TB
Dokumen ini adalah estimasi awal untuk keperluan perencanaan dan diskusi. Angka final ditetapkan setelah validasi kebutuhan bersama Bidang Pidana Militer dan unit TI Kejaksaan RI.
